Viewer-first design system

The running Viewer is the canonical visual reference for Markdown Plus. New surfaces reuse its semantic colors, system typography, radii, focus treatment, and state language.

Documentation follows runtime source. It does not introduce a second visual direction.

GitHub Alerts

Article notices inherit reader typography and paired theme status colors. Type labels remain visible without color; decorative glyphs use the approved application icon family. Switch Light/Dark to inspect the implemented contract.

Note

This is a GitHub-style note. It preserves Markdown and keyboard-accessible links.

Foundation

The interface uses a neutral blue-gray canvas, a white reading surface, compact rails, and semantic interaction states. Normal structure is separated by borders; shadows are reserved for temporary floating layers.

  • Blue communicates navigation, focus, and active selection.
  • Green communicates successful completion and saved state.
  • Amber communicates editing, dirty state, and warnings.
  • Red communicates failure and destructive actions.

Runtime layout

Read mode uses three tracks: Files, document content, and a right rail containing document actions plus Outline. The document article stays transparent inside the surface-colored content pane instead of becoming a raised card. Optional document statistics sit above Markdown without becoming part of exported or printed content. 

.mdp-body {
  grid-template-columns:
    var(--mdp-files-width)
    minmax(0, 1fr)
    var(--mdp-toc-width);
}

The location/count row uses plain text without a leading folder icon. Open/Switch folder uses a gold folder with a blue opening arrow to highlight workspace selection. Files keeps its title and the green Workspace badge in workspace mode. The details disclosure stays separate and uses an information-card glyph with metadata lines; only its small chevron turns when expanded, distinguishing it from folder-tree arrows. At rest, the closed control is muted on a transparent background; when expanded it uses primary text on a neutral panel background. Blue remains reserved for shared hover feedback and the focus ring. When closed, Open/Switch folder, Copy and Back/Leave are direct icon buttons and overflow only when space runs out. When expanded, Copy sits beside the filename. Open/Switch folder and Back/Leave workspace are separate full-width labeled buttons stacked inside the same card footer with a 6px gap. Back/Leave uses neutral text and inherited icon color in details and overflow, muted icons in the compact header, and the shared blue hover/focus feedback. The entire card collapses with details and navigation returns to the compact header actions. The metadata label, filename and path share one left edge; both footer buttons share their left and right edges. Full paths remain available through the title and accessible label. Menu icons and labels use fixed columns. Details remembers the tab preference and respects reduced motion; text actions stay at least 32px, or 44px on coarse pointers. This composition is Files-local. Source: ExplorerHeader and explorer.scss.

Expanded desktop sidebars share a two-row rhythm: Files keeps its existing UI structure; document actions and OUTLINE share the first row, followed by On this page and heading count. Fine-pointer rows are 36px / 44px with 12px before the lists; touch uses 52px rows and a separate label/action row on narrow panels. Porcelain #22 replaces both edge toggles. Existing mobile docks and editor policy remain.

Current geometry and state contracts are recorded in Sidebar composition, Panel toggles, and Sidebar scrolling. The standalone lists simulate auto-hide with native scrollbars; runtime uses the shared React overlay.

Interaction states

Document actions use Direct icons: Quick access (Updates, Theme), Document (View changes, Edit, Copy), and Output (Print, Export), separated by two quiet dividers. A measured prefix remains direct; the suffix moves into More in the same order. Theme retains blue moon / amber sun colors; Edit is amber and Save/copied feedback is green. Both sidebars use the Porcelain #22 tab: a 12 × 26px face, centered 12 × 16px chevron, mirrored accent dot, and one 580ms light pass on interaction. Hit areas are 24 × 44px or 44 × 44px on touch. The collapsed action rail remains 60px, with its first icon centered on the Show/Hide toggle and aligned with Files header icons on fine pointers. This fixture simulates commands only; runtime capability and editor policies are documented in Document actions.

Active rows use a soft blue fill and leading accent rail. Dense utility controls stay smaller than page forms on fine pointers, while interactive targets expand to 44px on coarse pointers. Focus always remains visible.

Extending the system

Unsaved editor changes use a compact confirmation with a warning badge, shared card and action footer. Keep editing receives focus; Discard changes uses the danger treatment. Escape and outside press cancel and return focus to the trigger.

Settings owns named custom-theme authoring, including colors and structured backgrounds; Popup only selects saved themes. Both surfaces derive shared controls from the same application foundations without introducing alternate focus or status semantics. Document updates uses the shared select treatment in Settings, with a bounded control column that stacks on narrow layouts. Its Viewer popover uses compact title/mode typography, semantic status indicators, a document-and-clock idle icon, a blue ready action, a slow sync glyph and a green completion check with smooth crossfades, a short-lived update speech bubble, and a bounded status card composed from the shared card, badge, notice, and button contracts. Change Review uses those same primitives together with shared status, action-footer, and empty/error-state treatments; only its diff table, changed-area navigation, and responsive two-pane layout remain Viewer-specific.
