# Planning

This directory contains active work that is not yet part of the documented product state, plus explicitly retained prototype labs. Labs link the implemented contracts under `docs/` and identify their remaining experiments.

- Keep each active effort in its own folder.
- Do not use planning documents as runtime truth.
- When work is complete, move durable behavior and architecture into `docs/`, then remove the plan.
- Use Git history for completed planning and implementation history; do not create an archive folder.

Current active work:

- [`design-system/viewer-refresh/`](./design-system/viewer-refresh/) — proposed Quiet Workspace viewer layout with an offline interactive demo, custom-theme scenes and split/focus edit states; not applied to runtime.
- [`design-system/git-changes/`](./design-system/git-changes/) — proposed current-file Git Changes: feature/behavior spec, interactive review prototype, change map, retained feasibility findings and verification boundaries; spike code removed from the extension for the first release, product feature not implemented.
- [`chrome-web-store/`](./chrome-web-store/) — release preparation, demo data, and artwork working files; approved upload images live in [`assets/chrome-web-store/`](../assets/chrome-web-store/).
- [`brand/`](./brand/) — retained local icon concepts; approved brand artwork lives in [`assets/brand/`](../assets/brand/).
- [`product-feature-roadmap/`](./product-feature-roadmap/) — remaining product opportunities, validation questions, and the [Document Updates browser checklist](./product-feature-roadmap/document-updates-manual-test.md); shipped Watch/Change Review behavior is documented under [`docs/`](../docs/document-updates-and-change-review.md).
