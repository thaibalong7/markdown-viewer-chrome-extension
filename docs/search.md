# Find and workspace search

This is the current runtime contract, released in version 1.0.1. Release/package availability is tracked separately in [CHANGELOG.md](../CHANGELOG.md). For everyday instructions, see [Find in a document or across files](../README.md#find-in-a-document-or-across-files).

## Commands and scope

| Command | Scope and action |
| --- | --- |
| Cmd/Ctrl+F or document Find action | Rendered reading content; focused CodeMirror retains native Find/Replace. |
| Ctrl+Shift+F or Files magnifier | Supported text-file contents in the current Folder/Workspace. macOS uses Control, not Command. |
| Browser-menu Find | Page text currently in the DOM, including visible sidebars; unmounted virtual rows are unavailable. |
| Enter in the workspace query / Search again | Start immediately and bypass the source cache for the current file list; use the active dirty draft instead of disk for that file. |
| Refresh file list | Rescan file membership using the explorer workflow; this is separate from rereading search contents. |

Cmd/Ctrl+F opens Find in the current reading surface. Find in document is also available in the document action toolbar or its More menu for registered text formats. Focused CodeMirror keeps its own Find/Replace; in editor focus mode the document Find command opens CodeMirror's search panel. Native browser page Find remains available from the browser menu, including sidebar text currently in the DOM. It cannot reliably search unmounted virtual Files/Outline rows.

Find is a sticky, right-aligned, opaque utility surface within the content pane. It occupies space at the top so it does not cover the first heading. Literal matching supports a current/total counter, previous/next controls, Enter/Shift+Enter wrapping, an explicit clear-query control, and Escape with focus return. Selected document text seeds the query. Both search inputs suspend pending work during IME composition and debounce only after the committed text is available; Enter/Escape used by the input method do not trigger search/navigation/dismissal. No results offers an explicit Search workspace action retaining the query; scope never expands automatically.

Both reading Find and file-content Search expose three in-memory matching toggles beneath the query: Match case (Aa), Match whole word (underlined ab), and Match diacritics (Á). Defaults are case-insensitive, substring and diacritic-sensitive. Whole-word boundaries use Unicode letters, numbers, combining marks and underscore; enabling it excludes `phải` when querying `hải`. Turning off diacritic matching lets `hai` match `hải` and `duong` match `đường`, including canonically equivalent decomposed text. Modes combine, remain shared across scope changes and result activation, and invalidate pending searches when changed. They survive closing/reopening search within the mounted Viewer, but are not persisted settings. Matching is literal; the typed query is never treated as a regular expression. Normalization maps back to original UTF-16 offsets, preserving full base/mark clusters, source excerpts and navigation. Focused CodeMirror retains its native Find controls.

The reading search indexes rendered text, including code spans, excluding hidden content, SVG, controls and UI state messages. CSS Custom Highlights paint matches without rewriting sanitized DOM, replacing syntax spans, changing selection, or adding text to copy/export. Opaque yellow marks all occurrences; opaque orange and a range-sized underline/gutter indicator identify the current match. Its React marker is portaled outside the article and follows/clips to scrolling and layout without modifying content. Replacing document nodes rebuilds the index; closing Find or destroying the viewer clears highlights and observers. Images have no searchable reading text. Mermaid source is searchable in raw mode or through workspace search.

Control+Shift+F opens file-content Search on all platforms; on macOS this means Control, not Command. The Files magnifier toggles the same search and exposes pressed/expanded state. Files title, details, location/count and toolbar remain mounted and stationary. Only the tree body changes: a compact query/close row, scope hint, progress/stop/retry and file-grouped snippets appear in its place. Both tree and Search bodies retain geometry in one grid cell, with immediate, motion-free switching; inactive layers are inert and accessibility-hidden. Closing restores focus to the magnifier and the existing tree scroll/expansion state. Query changes do not animate individual results. Results reuse ViewerScrollbar. Narrow screens retain the Files overlay; edit mode preserves the mounted readers and draft.

Search automatically uses the scope already shown in Files, both the current Folder tree and an explicitly selected Workspace. No additional folder selection is required when Files can enumerate that tree. Labels distinguish Search folder from Search workspace. The scanned tree is searched independently of expanded/virtual rows, respecting ignore policy, registry and depth/file/folder limits. A flat sibling fallback is searchable but explicitly incomplete because subfolders may be absent. Markdown, TXT, SQL, DBML and Mermaid source are searched; images and OCR are excluded. Only an absent/unreadable scope offers Choose folder, and opening Search never launches a picker automatically. During Folder or Workspace scans, Search waits and offers scan cancellation. Scope/query changes, closing Search and teardown invalidate pending work. Search uses scope-owned RAM caches only; no file-content index is persisted and no extension permission is added.

Results use compact file groups with an icon, basename, muted parent path and count. Filename and snippet text share one left axis: a 2 px row inset, 28 px line-number gutter and 8 px gap replace accumulated nested indents. Each match occupies one line (28 px with a fine pointer, 44 px with a coarse pointer), showing its source line number and short context around a highlighted hit. Context is bounded to 12 characters before and 48 after the hit; flex truncation gives the hit priority over surrounding text. The activated row has a stable selection indicator.

## Request and result lifecycle

Results are search-time snapshots; Search again bypasses source-cache reuse to verify disk/draft contents. Query changes can reuse cached source and normalized Unicode maps. When cache is used, the scope hint explains that Search again reads the latest files. Typing retains the previous rows, selection, file disclosure state and scroll position while waiting for replacement results. An Updating results status and disabled/muted rows identify the old snapshot; it cannot be activated with a newer query or mode. New hits replace it progressively; a completed zero-hit search clears it. Clearing the query or changing folder scope clears old results. Enter and Search again cancel the pending timer and start immediately; typing retains the 250 ms debounce. Stop also cancels a waiting timer. Stopped/failed old snapshots remain read-only until refreshed. Activation revalidates the selected file instead of trusting cached offsets and uses existing navigation and dirty/save protection. Navigator preserveFocus applies to same-file, cross-file and forced reload paths. If a clean displayed snapshot differs from the selected file version, activation refreshes it once through the guarded document lifecycle; dirty drafts are never silently reloaded. An active editor reveals the exact draft range. Otherwise, consistent source-line/occurrence mappings select the rendered range and highlight it without opening the Find utility or focusing its input. Clicking a result retains focus on its row; editor reveal also preserves list focus. Explicit Cmd/Ctrl+F opens Find. Closing file-content Search or changing its query clears the passive reading highlight. In the active Search panel, Up/Down moves focus through visible, expanded result rows without opening them; Down/Up from the query enters the first/last visible row. Native Enter/Space opens the focused row. F4/Shift+F4 opens the next/previous visible result, wrapping across file groups and retaining list focus. Pending/stale results, composition and open modal dialogs block result navigation. Hidden Markdown syntax, link destinations or ambiguous mappings open a read-only source dialog at the exact highlighted source location. Changed offsets/snippets prompt a fresh search. Snippets and source dialogs use literal React text, never source HTML.

## Limits

Workspace queries debounce for 250 ms; reading Find debounces for 100 ms. Queries are capped at 512 UTF-16 code units. Workspace reads are sequential through `documents/document-loader.js`, replacing disk source with the active unsaved draft. Files and drafts are capped at 2 MiB UTF-8 data and 2 Mi UTF-16 code units, output at 2,000 matches, and new reads stop after a 15-second budget. Already-dispatched background reads cannot be physically revoked; late results are ignored after cancellation. Oversized/unreadable files count as skipped. Stopped/limited/failed scans and searches have explicit partial-result UI, distinct from a complete zero-result search. Existing tree-scan limits also mark results partial. Reading Find caps indexed text at 2 Mi UTF-16 code units and 2,000 matches, with a limit notice. Block separators and BR nodes cannot push the index past the cap or create negative ranges. Its DOM index is reused across queries until document identity/visibility/content mutations invalidate it; navigation controls are disabled while a replacement query is pending.

## RAM cache and matching worker

Each current Files scope owns a conservative 16 MiB source LRU. Handle-backed files validate a fresh File size/lastModified tuple before reusing source. File URLs and snapshot readers reuse source for up to 5 seconds; Save/Watch changes visible in the active document baseline invalidate reuse. Short-lived failures are cached for non-handle readers to avoid repeatedly fetching oversized/inaccessible files. Explicit Search again retries them. Draft text always overrides disk data and cannot be reused as a disk entry after Save/exit edit mode. An identical reread retains its worker version key and prepared maps.

Cache freshness depends on the reader:

| Reader | Ordinary query | Enter / Search again / clean-result revalidation |
| --- | --- | --- |
| Real `file:` URL | Reuse a valid source entry for up to 5 seconds; reread after expiry or a known active-document change. | Reread through the bounded background/offscreen loader. |
| FileSystemFileHandle | Call `getFile()` and compare size/lastModified; reuse source only when its metadata and known document baseline match. | Read a fresh File snapshot and its contents. |
| Snapshot-only File from fallback folder picker | Reuse cache or read the same selected File snapshot. | Reread that snapshot; it cannot observe later disk changes. Reselect the folder to obtain new File objects. |
| Active dirty document | Search the current editor draft. | Search that draft; never replace it with disk text. |

Content search does not rescan directories. Every query still visits the current searchable file list and matches each available source; RAM caching avoids redundant I/O/normalization, rather than providing an inverted keyword index. Search again does not discover newly created files or update renamed/deleted tree entries. Refresh file list uses the existing explorer rescan/reselection path to update membership and its ignore/scan boundaries. Neither a warm cache nor a forced reread can provide live disk freshness for a snapshot-only workspace. Watch observes the active document separately, not every workspace file.

In-flight I/O is coalesced across ordinary query cancellation, so typing the next query can consume the same completed read. Changing the known reader/document revision prevents joining an older read. Scope replacement/viewer teardown aborts source jobs, clears the source LRU and releases its worker namespace. Closing the panel cancels query work but retains the scope cache for reopening. These are estimated data budgets, not total browser-process memory limits.

The extension background validates bounded SEARCH_TEXT messages and forwards them to the existing offscreen document. That extension-origin document lazily starts a packaged dedicated Worker; no blob/eval worker, new host permission or lower browser-security setting is used. The offscreen creation reasons include WORKERS alongside its existing local-file role. The Worker owns a shared conservative 32 MiB/256-entry LRU of source plus two diacritic variants, using typed UTF-16 offset maps. Case/whole-word toggles reuse those variants. Warm jobs send version keys instead of resending file content; cache eviction/restarted workers request the source again. Released namespaces reject late queued jobs. Worker errors/timeouts produce a failed-search state rather than silently doing heavy matching in the reader UI. Non-extension test/preview hosts use the same bounded store locally.

Local file reads with a byte budget propagate it through background messaging to offscreen XHR. Progress aborts oversize transfers; final array-buffer validation happens before UTF-8 decoding/serialization, with no unbounded fallback retry. Sequential content I/O still uses document-loader ownership. Match results publish on the first hit, at roughly 75 ms intervals, and at completion, instead of rebuilding the React result list after every warm file. Worker replies already yield the UI event loop; local callers yield cooperatively in batches.

Reading Find retains at most 16 MiB of prepared matching data for the current document, independently of workspace source caches. Its index/preparation cache is invalidated by renderer-owned DOM replacement and relevant mutations. Full persistent indexes, trigram indexes, result virtualization and filesystem-wide live watching are outside this iteration.

ViewerShell keeps the explorer mounted during editing. The bridge supplies current source/draft/editor state and virtual readers without moving I/O into components.

See the [design contract](./design-system/README.md#search) and [self-contained state specimen](./design-system/search.html). Automated tests cover offsets, DOM ownership, highlights, cancellation, stale reads/results, exact navigation, shortcuts, focus and action integration. Release QA should include Chrome 116, native menu Find, directory-picker permissions/virtual readers, native dirty-navigation confirmation, coarse pointers/reduced motion and large/slow/unreadable workspaces.

### Manual QA

1. Verify Cmd/Ctrl+F in reading, split editing and editor focus mode; verify browser-menu Find and Ctrl+Shift+F, including Control on macOS. Check query/close/icon focus and normal tree restoration.
2. Search Folder, handle-backed Workspace and snapshot-only Workspace; include nested collapsed/virtual rows, ignore rules, a partial flat list and a missing scope. Confirm opening Search never starts a picker automatically.
3. Combine case/whole-word/diacritic modes with Vietnamese `hải`, `phải`, `đường` and decomposed accents. Check IME commitment, clear, debounce, Enter, Stop and Escape; pending rows must not open under a newer query.
4. Open same-file and cross-file hits by mouse, Enter and F4/Shift+F4. Confirm list focus, passive highlight without opening Find, hidden-syntax source fallback and no adjacent glyph coverage in light/dark themes. Check narrow/coarse-pointer/reduced-motion states.
5. Use a disposable real file: warm-query reuse, changed metadata, forced Search again, a disk change between search and activation, dirty draft, Save and scope switch. For a snapshot-only folder, verify that new disk contents require reselection. Add/rename/delete test files and distinguish Search again from Refresh file list.
6. Cover oversized/unreadable files, 2,000-result and elapsed-budget notices, failed Worker startup/runtime messages, cancellation and viewer teardown. Confirm bounded reads and cache cleanup, and that delayed old I/O cannot replace newer results.

Automated coverage includes the actual navigator, Node Worker execution, bounded offscreen XHR and mocked Chrome routing. Browser fixtures verify packaged Worker execution and UI behavior, but do not replace loading the final unpacked extension on Chrome 116/current Stable with real file permissions and the offscreen lifecycle; those release checks remain unverified for this feature.
