Viewer-first design system

The running Viewer is the canonical visual reference for Markdown Plus. New surfaces reuse its semantic colors, system typography, radii, focus treatment, and state language.

Documentation follows runtime source. It does not introduce a second visual direction.

Foundation

The interface uses a neutral blue-gray canvas, a white reading surface, compact rails, and semantic interaction states. Normal structure is separated by borders; shadows are reserved for temporary floating layers.

  • Blue communicates navigation, focus, and active selection.
  • Green communicates successful completion and saved state.
  • Amber communicates editing, dirty state, and warnings.
  • Red communicates failure and destructive actions.

Runtime layout

Read mode uses three tracks: Files, document content, and a right rail containing document actions plus Outline. The document article stays transparent inside the surface-colored content pane instead of becoming a raised card. Optional document statistics sit above Markdown without becoming part of exported or printed content. 

.mdp-body {
  grid-template-columns:
    var(--mdp-files-width)
    minmax(0, 1fr)
    var(--mdp-toc-width);
}

Interaction states

Active rows use a soft blue fill and leading accent rail. Dense utility controls stay smaller than page forms on fine pointers, while interactive targets expand to 44px on coarse pointers. Focus always remains visible.

Extending the system

Unsaved editor changes use a compact confirmation with a warning badge, shared card and action footer. Keep editing receives focus; Discard changes uses the danger treatment. Escape and outside press cancel and return focus to the trigger.

Settings owns named custom-theme authoring, including colors and structured backgrounds; Popup only selects saved themes. Both surfaces derive shared controls from the same application foundations without introducing alternate focus or status semantics. Document updates uses the shared select treatment in Settings, with a bounded control column that stacks on narrow layouts. Its Viewer popover uses compact title/mode typography, semantic status indicators, a document-and-clock details icon that flips to a document-and-download action icon when a revision is ready, a short-lived update speech bubble, and a bounded status card composed from the shared card, badge, notice, and button contracts. Change Review uses those same primitives together with shared status, action-footer, and empty/error-state treatments; only its diff table, changed-area navigation, and responsive two-pane layout remain Viewer-specific.

Source of truth: src/theme/index.js, src/theme/backgrounds.js, src/shared/styles/**, and src/viewer/styles/**. Use the controls around the rails to preview theme and panel states.
